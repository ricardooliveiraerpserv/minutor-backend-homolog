# C6.1 — COMPILE MECHANISM PROOF · Protocolo de Execução (Operador on-prem)

> **Natureza deste documento:** instrumento experimental READ-ONLY. **NÃO** implementa C6,
> **NÃO** cria capability produtiva, **NÃO** altera o Minutor nem o C5. É o roteiro que um
> **operador humano com acesso on-prem** segue em **laboratório isolado** para provar
> empiricamente a física da compilação TOTVS antes de qualquer modelagem executável.
>
> **Status de governança no momento da emissão:** C5 = FINAL CLOSED / CONGELADO ·
> C6 executável = BLOQUEADO · C6.1 Discovery = PASS · P0–P7 = GO COM AJUSTES (A/B/C).

---

## 0. Quem executa, onde, e o que é proibido

**Executor:** operador humano com acesso físico/administrativo ao AppServer de laboratório.
(O sistema Minutor **não** executa esta prova — não há canal de compile e o agente é outbound-only.)

**Ambiente:** LAB / homolog **isolado**. **Zero produção.**

**Proibições absolutas durante toda a prova:**
- zero PRODUÇÃO · zero C5 · zero promote · zero rollback · **zero restart deliberado**
- não publicar RPO · não tocar target/RPO operacional ativo
- não implementar C6 · não criar migration/endpoint/capability · não alterar C5
- **nenhum secret, path sensível, hostname, username ou credencial** no relatório final

**Regra de sigilo do relatório:** capture **tipos** de informação, **nunca valores** sensíveis.
Logs brutos **permanecem on-prem**. O que volta para o gate arquitetural é evidência sanitizada.

---

## 1. Invariantes congelados (não violar; carregam do C6.0/C6.1)

1. `CompileInputIdentity` ≠ `CompileExecutionIdentity` ≠ `ArtifactIdentity` — **três identidades distintas**.
2. **Não assumir determinismo.** Mesmo input pode gerar bytes/digest diferentes até prova.
3. **Não deduplicar por `artifact_digest`.** Dedup futura só sobre **request lógico**.
4. **`CompileContextIdentity` NÃO tem fórmula/hash ainda.** Primeiro descobrir (P5) quais inputs
   realmente participam; só depois propor. Não inventar campos.
5. **Compile ≠ Publish.** A prova termina **antes** de qualquer fronteira destrutiva do C5.
6. **`ArtifactCandidate` pode não ser um "arquivo".** Ver Ajuste A / P1.5: se o compile modifica um
   RPO/APO **isolado**, o candidato correto pode ser **o RPO/APO isolado resultante inteiro**.

## 2. Ajustes mandatórios embutidos (A / B / C)

### Ajuste A — Artifact Boundary (antes de qualquer digest)
Provar fisicamente **o que o mecanismo TOTVS produz ou modifica** ao compilar 1 fonte. Classificar:
- **A.** standalone artifact · **B.** RPO/APO completo novo · **C.** mutação incremental de RPO/APO existente · **D.** outro.

Registrar por execução (form em P1.5/P2): `INPUT` · `TARGET BEFORE` · `OPERAÇÃO` · `TARGET AFTER` ·
`OBJETOS CRIADOS` · `OBJETOS MODIFICADOS` — **sem paths sensíveis**.
**Não** definir `artifact_digest` antes desta conclusão. **Não** assumir "fonte compilada = arquivo independente".

### Ajuste B — Suportado × Possível (na P1)
Classificar o mecanismo encontrado: **SUPPORTED** · **TECHNICALLY POSSIBLE** · **UNSUPPORTED/UNCERTAIN**.
Registrar: tooling TOTVS instalado · versão · doc/config associada · interface usada · suporte oficial? ·
já usado operacionalmente pelo cliente?
**PARE antes de compilar** se a única via for: automação de GUI · manipulação direta não documentada ·
hack de filesystem · protocolo interno não suportado · mecanismo de estabilidade indefensável.
**Não** transformar possibilidade técnica em arquitetura produtiva sem revisão.

### Ajuste C — Isolamento ampliado (gate obrigatório, sem telemetria nova)
`RPO_ACTIVE_BEFORE_HASH == RPO_ACTIVE_AFTER_HASH` **e** evidência observável de que:
- AppServer ativo **não** reiniciou · C5 **não** executou operação · active target **não** mudou ·
  **nenhum** promote/rollback · compile usou **exclusivamente** o target isolado ·
  RPO/filesystem operacional **sem** alteração funcional.

## 3. Plano experimental revisado — P0 → P7

> Em **qualquer** ambiguidade relevante em **P1** ou **P1.5**: **PARE e retorne o achado antes de P2.**

### P0 — Preparação
- [ ] AppServer **LAB** identificado (isolado de produção).
- [ ] Registrar `version / build / patch` do AppServer LAB.
- [ ] Confirmar **zero produção** no alvo.
- [ ] Selecionar **fonte controlada não-operacional** (ex.: 1 `.prw` trivial de teste).
- [ ] Identificar o **target de laboratório** (RPO/APO isolado onde o compile pousará).
- [ ] Capturar **`RPO_ACTIVE_BEFORE_HASH`** (hash do RPO operacional ativo — mesma noção do C5).
- [ ] Registrar **baseline operacional** (AppServer up? uptime? processo ativo?).

**Form P0**
```
LAB_APPSERVER_ID       : <rótulo não sensível>
VERSION / BUILD / PATCH: <...> / <...> / <...>
FONTE_CONTROLADA       : <nome lógico, ex. TESTE_C61.prw>
TARGET_LAB             : <rótulo do target isolado>
RPO_ACTIVE_BEFORE_HASH : <sha256>
BASELINE               : up=<sim/não> uptime=<s> processo=<id lógico>
```

### P1 — Descoberta do mecanismo
Descobrir, com evidência: mecanismo real · interface · parâmetros · autenticação exigida ·
**suporte oficial/operacional** (Ajuste B) · **existência de destination/target isolado**.

**Gate:** **se não houver mecanismo com target isolável → NO-GO** (não prosseguir).

**Form P1**
```
MECANISMO              : <descrição funcional, sem comando bruto sensível>
INTERFACE              : <CLI | serviço TCP de build | RPC | outro>
PARÂMETROS (tipos)     : <lista de tipos, sem valores sensíveis>
AUTENTICAÇÃO           : <tipo; NUNCA o segredo>
SUPORTE (Ajuste B)     : SUPPORTED | TECHNICALLY POSSIBLE | UNSUPPORTED/UNCERTAIN
JÁ USADO PELO CLIENTE? : <sim/não/desconhecido>
TARGET ISOLADO POSSÍVEL: <sim/não>  → se NÃO: NO-GO
```

### P1.5 — Artifact Boundary (Ajuste A) — **antes de considerar compile válido**
Determinar o **objeto físico** produzido/modificado. **Não** calcular identidade do candidate ainda.

**Form P1.5**
```
COMPORTAMENTO OBSERVADO: A(standalone) | B(RPO/APO novo) | C(mutação incremental) | D(outro)
UNIDADE FÍSICA DO CANDIDATE: <arquivo isolado | RPO/APO isolado inteiro | outro>
JUSTIFICATIVA          : <por que esta é a unidade correta>
```
> Se **C (mutação incremental)** e a única forma for mutar um RPO/APO **isolado**, avaliar se o
> `ArtifactCandidate` correto é **o RPO/APO isolado RESULTANTE inteiro** (não um "arquivo"). **Ambiguidade → PARE e retorne.**

### P2 — Compile A
Compilar **Input X + Context Y** no target LAB isolado.

**Form P2** (digest **só depois** de P1.5 definir a unidade física)
```
EXECUTION_IDENTITY_A   : <id lógico da execução>
OUTCOME                : succeeded | failed | timed_out | unknown  (COMO foi detectado: <...>)
DURAÇÃO                : <s>
OBJETOS CRIADOS        : <contagem/tipos, sem paths sensíveis>
OBJETOS MODIFICADOS    : <contagem/tipos, sem paths sensíveis>
ARTIFACT BOUNDARY      : <unidade física definida em P1.5>
ARTIFACT_DIGEST_A      : <sha256 calculado ON-PREM da unidade física>  (bytes NUNCA saem on-prem)
DIAGNOSTICS            : <classificados SAFE/INTERNAL/SECRET — só SAFE no relatório>
```

### P3 — Isolamento (Ajuste C) — gate obrigatório
Capturar `RPO_ACTIVE_AFTER_HASH` e as evidências ampliadas.

**Form P3**
```
RPO_ACTIVE_AFTER_HASH  : <sha256>
BEFORE == AFTER?       : <sim/não>          → se NÃO: NO-GO
APPSERVER RESTART?     : <não esperado>     → se sim: NO-GO
C5 EXECUTOU?           : <não esperado>     → se sim: NO-GO
ACTIVE TARGET MUDOU?   : <não esperado>     → se sim: NO-GO
PROMOTE/ROLLBACK?      : <nenhum>           → se algum: NO-GO
COMPILE USOU SÓ LAB?   : <sim>              → se não: NO-GO
RPO OPERACIONAL FUNCIONAL: inalterado       → se alterado: NO-GO
```

### P4 — Compile B (determinismo — NÃO exigido para PASS)
Mesmo Input X + mesmo Context Y conhecido. Comparar os **artefatos físicos** resultantes.

**Form P4**
```
ARTIFACT_DIGEST_B      : <sha256 on-prem>
A == B ?               : <sim/não>
SE DIFERENTE           : investigar QUAL parte variou (bytes/timestamps/metadados/context).
                         Digest diferente NÃO é falha automática do C6.
```

### P5 — Context Identity (descoberta; sem fórmula)
A partir da execução real, **listar os fatores observados** capazes de influenciar a saída.
**Não** criar hash/fórmula. Apenas o inventário empírico.

**Form P5**
```
FATORES OBSERVADOS QUE INFLUENCIAM A SAÍDA:
- AppServer/compiler   : <sim/não/como>
- version/build/patch  : <sim/não/como>
- flags/config         : <...>
- includes             : <...>
- dependencies         : <...>
- runtime/target       : <...>
- outros encontrados   : <...>
PROPOSTA (só listar, não fechar): candidatos a CompileContextIdentity = <lista>
```

### P6 — ADVPL / TLPP / FAILURE
Validar comportamento e observabilidade de outcome.

**Form P6**
```
ADVPL                  : compila? outcome confiável? <...>
TLPP (se suportado)    : mesmo mecanismo? diverge? <...>
FONTE INVÁLIDA         : falha detectável de forma confiável? <...>
WARNINGS               : obtidos? como? <...>
ERRORS                 : obtidos? como? <...>
```

### P7 — Diagnostics Boundary
Classificar os dados **reais** produzidos pelo compilador e propor estrutura sanitizada.

**Form P7**
```
CLASSIFICAÇÃO (tipos, sem valores):
- SAFE     : <ex.: código de erro, contagem de warnings, outcome>
- INTERNAL : <ex.: paths, nomes de includes, hostnames>  → NÃO cruza a fronteira por padrão
- SECRET   : <ex.: credencial/token/connection string>   → NUNCA cruza
PIPELINE PROPOSTO: raw(on-prem) → sanitizer → structured diagnostics(SAFE) → Minutor
```

## 4. Critérios de PASS da prova (todos obrigatórios; determinismo NÃO é exigido)

1. Mecanismo **invocável real** demonstrado.
2. Mecanismo **aceitavelmente suportado** (Ajuste B: não é hack indefensável).
3. Target **fisicamente isolável**.
4. **Unidade física do artifact identificável** (Ajuste A / P1.5).
5. **Artifact digest calculável localmente** (on-prem; bytes não saem).
6. **RPO operacional inalterado** (`BEFORE == AFTER` + evidências do Ajuste C).
7. **Nenhuma publicação implícita.**
8. **Nenhuma dependência de C5** para compilar.
9. **Sucesso/falha observáveis de forma confiável.**
10. **Diagnostics sanitizáveis** (SAFE isolável do INTERNAL/SECRET).
11. **Nenhum secret precisa chegar ao Minutor.**
12. **Provenance Source → Execution → Artifact** possível de registrar.

## 5. NO-GO imediato (qualquer um → parar e reportar)
- compile necessariamente escreve no **RPO ativo**;
- artefato **não** pode ser separado/identificado;
- **only compile+publish** (acoplados);
- mecanismo depende de **hack não aceitável**;
- **outcome não confiável**;
- **secrets** precisariam cruzar para o Minutor;
- **isolamento não demonstrável**;
- precisaria **alterar C5**.

## 6. Pontos de PARADA
- **P1 ou P1.5 com ambiguidade relevante** → PARE **antes de P2**, retorne o achado.
- **Qualquer NO-GO** (§5) em qualquer ponto → PARE, retorne evidência.
- **Ao concluir P7** → PARE. Entregue o **pacote de evidência** para novo gate arquitetural.
  **Não** implementar C6, migration, endpoint, capability; **não** alterar C5.
